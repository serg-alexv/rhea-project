# RHEA / RHEKNEL — semantic capsule

RHEA is evolving from a hook/filter bus into a phased runtime spine.
Its core value is not “intelligence”, but disciplined flow: action, judgment, commit.

The project’s real architecture is:
- mechanism in kernel,
- policy outside kernel,
- protocol between human and model(s),
- doctrine as constitutional pressure, not executable spec.

The key shift already happened:
- from Action/Filter toward Action/Judge,
- from loose callbacks toward verdict-capable execution,
- from chatty intuition toward protocolized coordination.

Main current risk:
semantic drift between artifacts.
`kernel.c`, `README`, protocol text, and manifesto no longer describe exactly the same object.

Main next move:
align identity and contracts.
Define what RHEA is, what it is not, and which semantics belong to kernel, protocol, or doctrine.

Coalition principle:
do not gather brands; gather roles.
Needed roles are synthesizer, adversary, dissenter, cartographer, verifier, and one human arbiter.

Consensus principle:
not “respect”, but epistemic good faith and symmetry of consideration.
Participants must steelman before critique, avoid author privilege, and converge only through non-contradictory reasoning.

Meet principle:
not a free-form group chat, but a governed procedure.
Independent pass → cross-attack → merge attempt → deterministic gate.

Deterministic gate matters more than eloquence.
Final acceptance must depend on tests, contracts, fuzzing, assertions, and failure behavior.

Continuity principle:
portable memory beats platform memory.
Preserve canonical text, compressed working memory, decision log, and protocol packet.

Deep thesis:
the project is becoming a constitutional runtime, not just a code artifact.
Its future depends on artifact alignment, formal contracts, disciplined dissent, and portable continuity.
