# Why this exists
User requested a digest of the conversation's hardest product signals ("CoTs and doubts" in user wording) and a team-absorbable transmission.

# 0) Invariant Definition (keep one, avoid drift)
Rhea hosts, records, and pressure-tests human gem-making (meaning discovery) under uncertainty.

Everything else (Tribunal / Atlas / Aletheia / game / cockpit / membrane / instrument) is a projection, interface, or module.
Do not multiply incompatible definitions.

# 1) Core ontology correction (critical)
The ontology is the main human interface, and it is transparent/invisible for most people.

Implication:
- UI is not the primary interface to reality.
- UI is the membrane/cockpit/notation that helps users see and reconfigure the ontology they are already thinking through.

# 2) Human signal model (what team must not forget)
Human reasoning signal is often alogical by design.
This is not noise and not necessarily error.

Operational properties:
- mixed motives
- contradictions held at once
- meaning appears before formal language
- feeling acts as a pre-verbal instrument signal
- discovery often begins as comparison/tension, not theory

Design consequence:
- Do not demand clean intent too early.
- Accept chaos; preserve signal; stabilize meaning gradually.

# 3) Gem doctrine (knowledge unit)
User term: GEMS = useful pieces of knowledge (few, valuable, reusable, pressure-tested)

Knowledge stack:
- data (raw observations)
- claim (interpreted statement)
- evidence (support/contradiction)
- relation (connection)
- model (organized structure)
- gem (proven/scoped invariant with consequences)

Minimal gem schema:
- statement
- scope
- provenance
- evidence_for
- evidence_against
- invariant_core
- failure_conditions
- confidence
- use (decision/prediction/action value)

Naming warning:
- Do not call generic memory-item counts "artifacts" if user protocol reserves "artifact/gem" for rare invariants.
- Use records/entries for broad counts.

# 4) Product-core method (user described, extremely important)
Rhea is not primarily an answer machine. It should support:
- raw intake of wild references
- blind comparison (everything to everything)
- feeling-led traversal / salience marking
- relation emergence between irrelevants
- gem extraction later
- pressure-testing with provenance

User-level formulation worth preserving:
- Rhea's core test: to gift many people many useful gems.

# 5) UI doctrine (absorbable, implementation-ready)
## 5.1 Entry/verification polarity
Pleasant entry, brutal verification.

Why:
- humans enter through attention/curiosity/mood/play
- rigorous testing can happen after engagement

## 5.2 Decoration doctrine
Decoration is not optional paint; it can be load-bearing interaction material.
Reject only decoration that competes with primary action without adding meaning.

## 5.3 Accepted UI doctrine lines (user-validated)
- sharp semantics + liquid transitions
- hard data + hot feel
- tiny exact details + impossible overall impression

Keep poles sharp; blur the transition, not the meanings.

## 5.4 Primary surface rule
One strong universal research composer is the center.
Everything else (providers, diagnostics, traces) is collapsible/secondary.

Primary composer must tolerate mixed inputs:
- question
- claim
- URL
- pasted notes
- snippets
- raw text

## 5.5 Anti-cartoon rule
Visible UI must be hardlinked to real state.
If motion/number cannot be traced to a source field/state variable, it is theater and should be removed or marked demo.

# 6) Oppositions (противопоставлений) as generator, not compromise
Do not flatten opposites into safe middle. Keep them sharp and build the connector.

Examples (user-derived):
- fancy + strong -> deterministic behavior under expressive skin
- feel hot + "wanna same but how" -> visible construction grammar (reproducible effect system)
- impossible + tiny little nothing -> micro-proof details carrying macro impression

Not "another note graph".
Potentially a missing class of tool:
- ontology-aware clarity instrument

- provenance-preserving, pressure-tested discovery
- beautiful membrane over harsh verification

# 9) Failure modes to actively guard against
- apophenia (false patterns that feel profound)
- aesthetic authority (beautiful UI makes weak claims look true)
- ontology lock-in (one frame hides alternatives)
- provenance debt (gems without receipts)
- over-structuring (kills alogical signal too early)
- under-structuring (vibe machine, no proofs)
