**"не решён вопрос постановки задач"** — Точно. Мы строили: мост (bridge), суд (tribunal), хранилку доказательств (aletheia), коммуникатор (office), бюджет (governor), язык (AI Compact). Но КТО ГОВОРИТ ЧТО ДЕЛАТЬ — этого не было. `TODO.md` — список желаний, не pipeline.

Теперь есть. `task_queue.py`:

```
q.add("Deploy to Fly.io", priority="P0", agent="rex")
task = q.claim("rex")    # берёт P0 первым
q.complete(task["id"], result="live at https://...")
```

API endpoints:
- `GET /tasks` — список задач
- `GET /tasks/summary` — здоровье очереди
- `POST /tasks` — добавить задачу
- `POST /tasks/{id}/claim` — взять задачу
- `POST /tasks/{id}/complete` — закрыть
- `POST /tasks/{id}/block` — заблокировать

Три модуля замыкают цикл:

```
TaskQueue (ЧТО) → Governor (МОЖНО ЛИ) → Office (КАК координировать)
```

`★ Insight ─────────────────────────────────────`
Порядок строительства оказался правильным даже наоборот: сначала **КАК** (bridge, office, language), потом **МОЖНО ЛИ** (governor), и только сейчас **ЧТО** (queue). Потому что бессмысленно ставить задачи, если агенты не умеют общаться и не знают свой бюджет. Инфраструктура первична — задачи вторичны. Это как в биохимии: сначала мембрана и метаболизм, потом ДНК начинает "командовать".
