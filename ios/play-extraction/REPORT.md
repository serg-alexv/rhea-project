## Component Structure Notes

The Firestore cache stores project documents (teamProjects collection) with this schema per document:
- `dateCreated`, `dateModified` - timestamps
- `display` - project ID reference
- `initialPageComponentId` - the root page component ID (163 unique IDs found)
- `isLocked` - boolean
- `jsonAvailable` - boolean (indicates if full project JSON is available server-side)
- `lastPatchAppliedDate` - timestamp
- `mediaVersion` - version string
- `name` - project name
- `ownerUserId` - Firebase Auth UID
- `productVersion` - Play.app version that last edited
- `projectVersion` - schema version (1.0.0)
- `teamId` - team document ID
- `thumbs` - map of page component IDs to thumbnail data:
  - `aspectRatio` - number
  - `availableSizes` - array of size configs (e.g., "14_Pro_Max")
  - `dateModified` - timestamp
  - `fileExtension` - "jpeg" or similar
  - `placeholderHex` - background color for loading state
  - `size.height`, `size.width` - dimensions

**No deep component trees in cache.** The Firestore local cache only stores the project metadata (name, owner, thumbnails). The actual component hierarchy (layers, actions, properties, colors, fonts, padding, spacing, etc.) is stored in separate JSON files that Play.app downloads on-demand (indicated by the `jsonAvailable` flag). These are NOT in the Firestore cache -- they would be in a separate local storage location or fetched fresh each time.
