## Selection rule

Start with the surfaces that reveal the system's real state:

1. `GovernorView` if you need risk and spend visibility.
2. `TeamChatView` if you need to see agent traffic.
3. `TasksView` if work coordination is primary.
4. `AletheiaView` if proofs and verification are the product core.
5. `BioRendererView` or `NodeEditorView` when the domain includes interactive science or workflow design.

Do not mount the whole package just because it exists. Pick the minimum set that gives a truthful operator surface.
