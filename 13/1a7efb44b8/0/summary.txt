`★ Insight ─────────────────────────────────────`
**Why the tier fallback design matters:** Each tier has an ordered candidate list. `ask_tier()` walks through candidates — skips providers with no keys, then tries the actual API call. If it gets an error, it moves to the next candidate. This means even with 6/7 providers dead, every tier still works because DeepSeek is reachable somewhere in each chain. The cascade is linear O(n) through candidates until one responds — no parallel waste on broken providers.

The `deepseek-reasoner` returning empty text is a quirk of R1-class models: they produce `reasoning_content` (chain-of-thought) separately from `content` (final answer). For simple prompts the CoT IS the answer and `content` is empty. LiteLLM doesn't merge these by default.
